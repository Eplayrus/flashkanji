# Flash Kanji router audit

Branch: `codex/router-validation-fix` from `codex/i18n-seo-architecture`.

## Current routing map

The single source of truth for route syntax is now `index/src/router.ts`.

| URL family | Valid shape | App route | Notes |
| --- | --- | --- | --- |
| SPA shell | `/`, `/index.html` | `home` | Main Vite entry. Hash decides the interactive section. |
| Legacy shell | `/index/`, `/index/dist/`, optional `index.html` | `home` | Redirected to `/` by `404.html` and dev/preview middleware. |
| Download | `/download/`, `/{locale}/download/` | `download` | Static SEO page also exists in `index/public/download/index.html`. |
| Localized home | `/{locale}/` | `home` | Locale comes from `index/public/locales/registry.json`. |
| Textbook hub | `/{locale}/textbooks/` | `textbooks` | Static SEO page. |
| Textbook level | `/{locale}/textbooks/n1/` … `n5/` | `textbooks` | Static SEO page; level must be N1-N5. |
| Kanji hub | `/{locale}/kanji/` | `dictionary` | Static SEO page. |
| Kanji page | `/{locale}/kanji/u4e0a-jou/` | `kanji` | Slug must match `uXXXX-romaji`; real files are generated by SEO tooling. |
| Hash home | `#home` or empty hash | `home` | Exact match only. |
| Hash simple routes | `#review`, `#dictionary`, `#download`, `#about`, `#writing`, `#stats`, `#achievements`, `#eva-room` | same route | No extra segments allowed. |
| Hash textbooks | `#textbooks`, `#textbooks/N5`, `#textbooks/N5/lesson-1` | `textbooks` | Level syntax and subroute syntax validated before render; lesson/entity validated in app data. |
| Legacy hash lessons | `#jlpt/n1/bulk-n1-01` | `textbooks` | Kept for old deep links, but matched strictly. |
| JLPT lesson overview | `#jlpt-lesson/N5` | `jlpt-lesson` | Level must be N1-N5 and exist in catalog data. |
| Hash kanji | `#kanji/card-id`, `#kanji/上`, `#kanji/u4e0a-jou` | `kanji` | Parameter is syntactically checked, then resolved against loaded cards. |
| Learn path | `#learn`, `#learn/lesson/n5-lesson-1`, `#learn/legacy/lesson-1` | `learn` | View and target id must be exact. |

Supported locale URL segments are read from `index/public/locales/registry.json` (`ru`, `en`, `es` at audit time). Unknown locale-like first segments return `unknown-locale`.

## Files and responsibilities

| File | Responsibility |
| --- | --- |
| `index/src/router.ts` | Route registry, hash parser, pathname matcher, canonical path normalization, hashchange installer, render cancellation helper. |
| `index/src/app.js` | Applies `RouteMatch`, validates route entities against loaded app data, renders SPA Not Found, writes route URLs through `replaceRouteUrl`. |
| `index/vite.config.ts` | Dev/preview middleware for `/download/`, legacy `/index...` redirects, and unknown HTML route 404 responses. |
| `index/public/404.html` | Real GitHub Pages 404 page. Only legacy `/index...` paths redirect to `/`; arbitrary unknown paths stay 404. |
| `index/tools/generate-seo.mjs` | Generates localized static SEO pages, sitemap files, `legacy-url-map.json`, canonical and hreflang markup. |
| `index/tools/seo-foundation.mjs` | Shared SEO helpers: canonical URL, locale paths, stable kanji slugs, hreflang link rendering. |
| `index/tools/validate-seo.mjs` | Checks sitemap entries, canonical self links, hreflang reciprocity and generated SEO content consistency. |
| `index/index.html` | Main app shell with default canonical/hreflang and internal nav buttons. |

## Findings before the fix

1. `parseHash()` treated any unknown hash as `"home"`. Example: `#does-not-exist` rendered Home.
2. `setRoute(route)` used a route array fallback to Home for unregistered route names.
3. Several route readers in `app.js` parsed `location.hash` with local regexes. Some accepted partial matches or malformed extra segments.
4. Textbook deep routes could fall through to overview or first available content when the subroute did not exist.
5. Missing kanji route entities rendered a generic “Kanji not found” block instead of the route-level Not Found state.
6. `index/public/404.html` converted arbitrary GitHub Pages 404 paths into hash routes, so a missing static page could become SPA Home.
7. Dev/preview could serve the app shell for unknown HTML pathnames, masking direct-open errors locally.

## Implemented routing scheme

`RouteMatch` now has two explicit states:

```ts
type RouteMatch =
  | {
      status: "valid";
      route: AppRoute;
      locale: SupportedLocale;
      params: Record<string, string>;
    }
  | {
      status: "not-found";
      reason:
        | "unknown-locale"
        | "unknown-route"
        | "invalid-parameter"
        | "entity-not-found";
    };
```

The router performs syntax matching only. `app.js` performs entity checks against current app data:

- kanji id / literal / public slug must resolve to a real card after deferred data is loaded;
- textbook level must exist in JLPT catalog;
- textbook subroute must be one of the supported sections or a real lesson id;
- `#jlpt-lesson/Nx` must resolve to a catalog lesson;
- learning path node / legacy lesson ids must exist.

Unknown routes now render a SPA Not Found page with `data-route-error="not-found"`, `data-route-not-found="<reason>"`, `robots: noindex, follow`, and canonical `/404.html`.

## GitHub Pages and static 404 behavior

`404.html` is no longer a broad SPA redirect. It only redirects legacy shell URLs:

- `/index/`
- `/index/dist/`
- `/index/index.html`
- `/index/dist/index.html`

All other missing URLs stay on the real 404 page. This prevents broken public URLs such as `/en/kanji/u4e0a-ue/` from becoming duplicate Home content.

Dev and production preview now mirror this behavior for HTML requests: if a pathname is not backed by a static `index.html` file and is not the app shell, Vite serves `404.html` with HTTP 404.

## Canonical and hreflang notes

Generated SEO pages keep self-referencing canonical links and reciprocal hreflang via `generate-seo.mjs` / `seo-foundation.mjs`. `validate-seo.mjs` verifies:

- canonical equals the sitemap URL;
- no noindex page is present in sitemap;
- hreflang alternates point to generated sitemap pages;
- alternate links are reciprocal.

SPA Not Found explicitly switches runtime metadata to noindex and canonical `/404.html` so unknown hash routes do not look indexable.

## Valid / invalid URL examples

| URL | Expected result |
| --- | --- |
| `/` | valid app shell / Home |
| `/download/` | valid download page |
| `/en/textbooks/n1/` | valid static N1 textbook SEO page |
| `/en/kanji/u4e0a-jou/` | valid static kanji SEO page if generated file exists |
| `/#review` | valid Review |
| `/#textbooks/N5/lesson-1` | valid N5 lesson |
| `/#jlpt/n1/bulk-n1-01` | valid legacy N1 lesson route |
| `/#kanji/上` | valid only if card exists |
| `/en/kanji/u4e0a-ue/` | HTTP 404 if no generated file exists |
| `/review` | HTTP 404 / unknown route |
| `/xx/` | HTTP 404 / unknown locale |
| `/en/kanji/not-a-slug/` | HTTP 404 / invalid parameter |
| `/#does-not-exist` | SPA 404 / unknown route |
| `/#textbooks/N9` | SPA 404 / invalid parameter |
| `/#textbooks/N5/not-real-lesson` | SPA 404 / entity not found |
| `/#kanji/not-real-card` | SPA 404 / entity not found after card data validation |
